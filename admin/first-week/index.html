도입 첫 주 점검표

Fortress AI 2.6.1 · 게이트웨이 3.3.0 기준

이럴 때 봅니다

  • Fortress AI를 막 도입해 첫 주에 무엇부터 점검할지 정할 때
  • 임직원 계정을 빠짐없이 발급했는지 확인할 때
  • 정책 배포와 샌드박스가 PC마다 제대로 설정됐는지 확인할 때

첫 주가 끝나면 PC마다 위 화면처럼 점검이 모두 정상으로 끝나야 합니다.
항목 끝의 링크에 자세한 순서가 있습니다.

1. 설치 방식을 정합니다​

  • 개발자 PC에 설치할지, 공용 개발 서버에 한 번 설치할지 정합니다. 설치 방식과 점검
  • 게이트웨이에서 받을 수 없는 환경이면 설치 패키지를 반입해 설치 스크립트로 설치합니다. 설치 패키지로 설치하기
  • 사용자에게 안내할 게이트웨이 주소를 정합니다. 설치에 관리자 권한은 필요하지 않습니다.

2. 계정을 발급하고 전달합니다​

  • 설치 담당자에게 장비 주소와 첫 관리자 admin의 비밀번호를 받습니다. 도입 첫날
  • 관리 화면(<장비 주소>:8080/admin)에 로그인해 첫 관리자 비밀번호를 바꿉니다. 관리 화면 로그인
  • 관리자 계정을 두 명 이상 둡니다. 유저 추가에서 관리자 스위치를 켜고 만듭니다. 두 번째 관리자 만들기
  • 유저관리에서 임직원 계정을 만듭니다. 여러 명 추가를 했으면 처음 비밀번호를 모두 복사로 그 자리에서 옮겨 둡니다. 임직원 계정 만들기
  • 사용자 화면의 전할 안내를 안내 복사로 보내고, 처음 비밀번호는 따로 전합니다. 계정 정보 전달
  • 유저관리 목록에서 임직원마다 마지막 로그인 시각이 보이는지 확인합니다. 로그인 확인

3. 관리자 정책을 배포합니다​

  • 게이트웨이 3.3.0에서는 PC에 정책 파일을 두어 배포합니다. Windows는 그룹 정책이나 Intune으로 배포합니다. 관리자 정책
  • 게이트웨이 3.4.0 이상이면 관리 화면의 관리 정책에서도 배포합니다. PC 파일과 함께 쓰면 PC 파일에 managedGatewayUrl을 적습니다. 파일이 정한 키는 파일 값이 우선합니다. 우선순위
  • about에 정책의 이름과 버전을 적습니다. 사용자의 보안⁠·⁠감사 화면에서 적용 여부를 확인합니다.
  • 사내 패키지 저장소 주소는 packageMirrors와 allowedDomains에 함께 넣고, IP 주소가 아닌 호스트 이름으로 씁니다.

4. Windows PC의 샌드박스를 켭니다​

  • Windows에서는 샌드박스가 기본으로 꺼져 있습니다. 꺼져 있으면 명령에는 권한 확인(안전망)만 남습니다.
  • 전용 계정 방식과 MXC 방식 중 하나를 고릅니다. Windows 샌드박스 켜기
  • 전용 계정 방식이면 PC마다 관리자 권한으로 fortress windows-install을 한 번 실행합니다. 여러 사람이 쓰는 PC는 --skip-profile-grant를 붙입니다.
  • 정책에서 sandbox.enabled를 켭니다.

5. 설치한 PC를 점검합니다​

  • fortress doctor로 로그인, 모델 서버, 게이트웨이, 관리 정책, 샌드박스를 점검합니다. PC에 둔 정책 파일이면 관리 정책 줄에 "파일"과 그 경로가 나옵니다. 확인하는 법
  • 정책 파일이 JSON으로 읽히지 않으면 모든 도구 호출을 거부합니다. 배포한 뒤 fortress doctor로 확인합니다.
  • 사이드바의 보안⁠·⁠감사에서 전송 대상이 "이 서버만"으로, 외부 버전 확인⁠·⁠원격 측정⁠·⁠자동 설치⁠·⁠세션 업로드가 "꺼짐"으로 표시되는지 봅니다.
  • 샌드박스 칸에서 상태와 네트워크 허용 범위를 봅니다.
  • 게이트웨이 3.4.0 이상에서 정책을 배포했다면 관리 화면 관리 정책의 아래 표에서 사용자마다 적용 여부와 샌드박스 상태를 봅니다. 받았는지 확인하는 법

6. 사용자에게 안내합니다​

  • 설치하고 첫 요청 보내기를 보냅니다.
  • 업무 담당자에게는 업무별로 해 보기를 함께 보냅니다.
  • 결과는 담당자가 확인하고 쓴다는 점을 알립니다. 에이전트가 읽은 파일과 실행한 명령은 타임라인에서 차례로 볼 수 있습니다.
  • 개인정보가 든 파일은 그 값을 지우거나 가린 사본을 작업 폴더에 넣고, 원본을 둬야 하면 권한 규칙으로 읽기를 막도록 알립니다. 입력 가림은 입력창에 쓴 글에만 적용됩니다.

7. 첫 주 끝에 기록을 봅니다​

  • 보안⁠·⁠감사에서 거부만 골라 무엇이 막혔는지 봅니다. 거부 사유는 결과 칸에 표시됩니다.
  • 필요하면 CSV 내보내기로 받습니다. 지금 화면에 보이는 기록만 내보냅니다.
  • 감사 로그는 각 PC에 남습니다. 여러 PC의 기록을 모으려면 각 PC의 기록 파일을 수집합니다. 게이트웨이 관리 화면에는 감사 로그가 모이지 않습니다. 감사 로그
  • 관리 화면의 감사 기록에서 첫 주 동안의 계정⁠·⁠로그인 기록과 로그인 실패를 봅니다. 감사 기록 메뉴
  • 유저관리의 30일 안 씀 탭에서 아직 쓰지 않은 계정을 봅니다.
  • 토큰 사용량의 유저별 표에서 첫 주 사용량을 봅니다. 아직 쓰지 않은 사람에게는 체험 첫날을 보냅니다. 토큰 사용량

다음에 볼 글

도입 첫날: 계정 발급과 전달장비 설치 뒤 고객사 관리자가 관리 화면에 로그인해 비밀번호를 바꾸고, 임직원 계정을 발급해 전할 안내와 처음 비밀번호를 전달하고, 임직원이 로그인했는지 확인하는 순서입니다.관리 화면 둘러보기게이트웨이 관리 화면의 메뉴, 관리자와 사용자의 차이, 계정 추가·비밀번호·사용 중지와 다시 사용, 사용량과 호출 기록, API 키, 로그인한 기기, 감사 기록, 기록 보관 기간입니다.관리자 정책조직 공통 규칙을 PC의 정책 파일로 배포하는 방법, 게이트웨이 3.4.0 이상의 관리 정책 화면, 둘이 겹칠 때의 우선순위, 받았는지 확인하는 법입니다.
