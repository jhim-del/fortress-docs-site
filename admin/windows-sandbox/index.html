Windows 샌드박스 켜기

Fortress AI 2.6.1 기준

이럴 때 봅니다

  • Windows PC에서 에이전트의 명령을 샌드박스 안에서 격리해 실행하고 싶을 때
  • 전용 계정 방식과 MXC 방식 중 하나를 골라야 할 때
  • 여러 사람이 함께 쓰는 Windows PC에 설치할 때

Windows에서는 (명령을 격리하는 장치)가 기본으로 꺼져 있습니다.

꺼져 있으면 명령은 샌드박스 없이 실행되고, 실행 전 권한 확인(안전망)만 남습니다(한 장으로 보는 보안).

Windows 방식은 알파 단계입니다.

두 가지 방식​

전용 계정 (기본)MXC 컨테이너
정책 값"sandboxuser""mxc"
쓸 수 있는 PCWindowsWindows 11 24H2(26100.9278 이상), 25H2(26200.9278 이상)
관리자 설치PC마다 fortress windows-install을 한 번필요 없음
명령 도구bash(Git Bash). 정책으로 PowerShell 도구를 더할 수 있습니다.PowerShell과 cmd만. bash 도구가 없습니다.
읽기사용자 프로필은 도구 폴더와 패키지 설정만 읽힙니다.시스템 드라이브에서 읽기 금지 목록 밖은 모두 읽힙니다.
쓰기NTFS 권한으로 작업 폴더 밖 쓰기를 막습니다.작업 폴더와 쓰기 허용 폴더만 됩니다. PC의 임시 폴더에는 쓸 수 없습니다.
외부 접속Windows 방화벽이 그 계정의 바깥 연결을 막습니다.샌드박스의 프록시로만 나가고 주소마다 묻습니다. 이 PC의 로컬 서버에는 접속하지 못합니다.
쓸 수 있는 곳데스크톱. ssh 세션에서는 시작되지 않습니다.로그인한 데스크톱에서만
못 켜질 때설치 전이면 fortress windows-install을 안내하고 샌드박스 없이 실행합니다.전용 계정으로 넘어가지 않고 꺼집니다. 이유를 한 번 알립니다.

Git Bash가 필요한 PC는 전용 계정 방식으로 둡니다.
읽기 범위를 좁게 두고 싶을 때도 전용 계정 방식이 맞습니다.

전용 계정 방식 켜기​

  1. 관리자 권한으로 아래 명령을 실행합니다. 사용자 계정 컨트롤 확인이 한 번 뜹니다. 
    fortress windows-install
  2. 정책 파일에 아래 항목을 넣습니다. 사용자 정책(~/.fortress/agent/policy.json)이나 관리자 정책에 둡니다. 
    { "sandbox": { "enabled": true } }
  3. 일반 권한 터미널에서 상태를 확인합니다. 샌드박스 줄에 "켜짐"이 나오면 끝입니다. 
    fortress doctor

설정 명령은 다시 실행해도 안전합니다.
되돌리려면 fortress windows-uninstall로 계정과 방화벽 규칙을 지웁니다.

주의

fortress windows-install만 관리자 권한으로 실행합니다.
fortress를 관리자 권한으로 띄우면 샌드박스 밖의 명령도 관리자 권한으로 실행되어, 시작할 때와 fortress doctor가 경고합니다.

여러 사람이 쓰는 PC​

fortress windows-install은 샌드박스 안 명령이 사용자 프로필의 도구 폴더와 패키지 관리자 설정 파일을 읽을 수 있게 합니다.
문서, 바탕 화면, 다른 프로젝트, ~/.fortress 같은 그 밖의 프로필은 읽히지 않습니다.
이 읽기 권한은 PC의 샌드박스 그룹에 걸리므로, 여러 사람이 쓰는 PC에서는 다른 로컬 사용자의 샌드박스 명령도 이 폴더를 읽습니다.

그런 PC는 아래처럼 설치하고, 다시 설치할 때도 늘 이 옵션을 붙입니다.

fortress windows-install --skip-profile-grant

이 옵션은 권한을 새로 걸지 않을 뿐, 이전 설치가 건 권한을 지우지는 않습니다.
남아 있으면 설치가 그렇게 알립니다.

MXC 방식 켜기​

사용자 정책이나 관리자 정책에 아래 항목을 둡니다.
관리자 설치는 필요 없습니다.

{ "sandbox": { "enabled": true, "windows": { "backend": "mxc" } } }

fortress doctor를 실행해 샌드박스 줄을 봅니다.
"켜짐 (MXC 컨테이너, powershell 도구만 (bash 도구 없음))"이 보이면 쓸 수 있습니다(맨 위 화면).

  • 관리자 정책의 값이 우선합니다. 프로젝트 폴더의 정책에 둔 값은 읽지 않습니다.
  • 임시 폴더는 명령마다 새로 만들고 끝나면 지웁니다. 패키지 관리자 캐시가 명령 사이에 남지 않습니다.
  • 현재 사용자 레지스트리(HKCU)는 컨테이너 안에서 읽힙니다. 값에 비밀번호나 토큰을 두는 프로그램이 있으면 그 값도 읽힙니다.
  • 더 막을 곳은 정책의 sandbox.filesystem.denyRead에 둡니다.
  • 명령 하나에 컨테이너를 여는 시간이 약 0.35~0.45초 붙습니다.
  • 방식을 바꾸면 fortress를 다시 시작합니다.

MXC 방식에서는 에이전트가 명령을 PowerShell로 실행합니다.
웹 화면의 입력창 아래와 환경 칸에는 다른 방식과 같이 샌드박스 켜짐이 보입니다.

확인하는 법​

  • fortress doctor의 샌드박스 줄을 봅니다. 못 켜졌으면 이유가 나옵니다.

    방식켜졌을 때 샌드박스 줄
    전용 계정켜짐 (srt-win, srt-sandbox 계정)
    MXC 컨테이너켜짐 (MXC 컨테이너, powershell 도구만 (bash 도구 없음))

  • 웹 화면에서는 입력창 아래 칩과 대화 화면 오른쪽 환경 칸에 샌드박스 켜짐 또는 주황색 샌드박스 꺼짐이 보입니다.

  • 터미널 화면에서는 샌드박스가 꺼져 있으면 상태 줄에 sandbox: off가 보입니다.

  • 정책으로 켰는데 켜지지 못했으면 처음 한 번 알립니다. 관리자 정책이 required면 명령을 막습니다.

자세히: 전용 계정 방식을 켠 뒤 달라지는 점
상황동작대처
로그인이 필요한 git 원격 저장소로그인 창을 띄우지 않고 실패합니다. 공개 저장소는 그대로 됩니다.그런 저장소는 사람이 터미널에서 받습니다.
일부 도구의 HTTPS 연결설치 패키지에 든 Git Bash의 curl은 허용한 주소에도 HTTPS 연결이 실패합니다.HTTP 연결과 git의 HTTPS는 됩니다.
관리자 권한으로 만든 폴더그 세션만 샌드박스 없이 실행하고 이유를 보여 줍니다.사용자가 권한을 가진 폴더에서 작업합니다.
ssh로 접속한 세션샌드박스가 시작되지 않습니다.데스크톱에서 씁니다.
다른 폴더의 대화를 열 때샌드박스를 다시 초기화해 잠깐 기다립니다.
