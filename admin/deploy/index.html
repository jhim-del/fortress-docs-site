설치 방식과 점검

Fortress AI 2.6.1 기준

이럴 때 봅니다

  • 개발자 PC에 깔지, 공용 개발 서버에 한 번 깔지 정할 때
  • 반입한 설치 패키지로 설치해야 할 때
  • 설치한 PC가 제대로 붙었는지 점검할 때

Fortress AI 클라이언트는 사용자 계정에 설치됩니다.
설치에 관리자 권한은 필요하지 않습니다.

두 가지 설치 방식​

개발자 PC에 설치공용 개발 서버 (ssh)
설치게이트웨이 설치 페이지의 명령 한 줄, 또는 설치 패키지의 설치 스크립트관리자가 root로 한 번 설치
로그인fortress login을 실행하면 브라우저가 열립니다.fortress login이 보여 주는 주소를 자기 PC 브라우저에서 엽니다. 또는 fortress login --headless로 터미널에서 로그인합니다.
웹 화면fortress web을 실행하면 열립니다.fortress web이 보여 주는 ssh -L 명령을 실행한 뒤 자기 PC 브라우저에서 엽니다.
샌드박스PC 운영체제의 것서버의 bubblewrap

사용자가 따라 하는 순서는 설치하고 첫 요청 보내기에 있습니다.

설치 패키지로 설치하기​

게이트웨이에서 받을 수 없는 환경에서는 반입한 설치 패키지로 설치합니다.

Linux 예
tar -xzf ax-fortress-<버전>-linux-x64.tar.gz
./ax-fortress-<버전>-linux-x64/install.sh

설치 위치​

macOS ⁠·⁠ LinuxWindows
설치 위치~/.local/share/fortress/<버전>/%LOCALAPPDATA%\Programs\fortress\<버전>\
실행 파일~/.local/bin/fortress사용자 PATH에 추가됩니다.
  • 같은 설치 스크립트를 다시 실행하면 그 버전으로 바뀝니다.
  • 이전 버전의 폴더는 남습니다. 필요 없으면 지웁니다.
  • 설치 뒤에는 fortress update가 로그인한 게이트웨이에서 새 버전을 받습니다.

설치 뒤 점검​

fortress doctor

fortress doctor는 아래 항목을 점검하고 고칠 것을 알려 줍니다.

항목점검 내용
로그인로그인 상태
모델 서버연결과 응답. 짧은 요청을 실제로 보내 봅니다.
게이트웨이버전 번호와 모델 서버 상태
관리 정책지금 읽는 관리자 정책의 출처. 게이트웨이에서 받았으면 주소와 버전, 받은 시각, 건너뛴 키가 나옵니다. PC의 파일이면 그 경로가 나옵니다.
샌드박스실제로 띄워 보고 상태를 확인합니다. 못 켜졌으면 이유가 나옵니다.

웹 화면에서는 설정 › 정보 탭 맨 아래의 점검 버튼이 같은 점검을 합니다.

주의

fortress를 관리자 권한으로 띄우면 시작할 때와 fortress doctor가 경고합니다.
대화는 일반 권한 터미널에서 엽니다.

Windows 샌드박스 준비​

명령하는 일
fortress windows-installWindows 샌드박스를 준비합니다. 관리자 권한으로 PC마다 한 번 실행합니다.
fortress windows-install --skip-profile-grant여러 사람이 쓰는 PC용입니다. 샌드박스 안 명령에 사용자 프로필의 도구 폴더 읽기 권한을 주지 않습니다.
fortress windows-uninstall준비한 계정과 방화벽 규칙을 지웁니다.

관리자 설치가 필요 없는 MXC 방식과의 차이는 Windows 샌드박스 켜기에서 봅니다.

다음에 볼 글

도입 첫 주 점검표관리자가 Fortress AI를 도입한 첫 주에 설치 방식, 계정 발급, 정책 배포, 샌드박스, 설치 뒤 점검, 사용자 안내, 기록 확인을 차례로 점검하는 목록입니다.관리자 정책조직 공통 규칙을 PC의 정책 파일로 배포하는 방법, 게이트웨이 3.4.0 이상의 관리 정책 화면, 둘이 겹칠 때의 우선순위, 받았는지 확인하는 법입니다.Windows 샌드박스 켜기Windows PC에서 샌드박스를 켜는 두 가지 방식(전용 계정, MXC 컨테이너)을 비교하고, 켜는 순서와 확인하는 법을 정리합니다.
