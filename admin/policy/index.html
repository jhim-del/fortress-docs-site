관리자 정책

Fortress AI 2.6.1 · 게이트웨이 3.3.0 기준

이럴 때 봅니다

  • 조직 전체에 같은 권한·샌드박스 규칙을 걸어야 할 때
  • 정책을 PC에 파일로 둘지, 게이트웨이에서 내려줄지 정할 때
  • 배포한 정책이 사용자 PC에 들어갔는지 확인할 때

관리자 정책은 사용자가 덮어쓸 수 없는 조직 공통 규칙입니다.
에이전트는 어느 모드에서도 정책을 읽거나 고칠 수 없습니다.

배포하는 두 가지 방법​

게이트웨이 3.3.0에서는 PC에 정책 파일을 두어 배포합니다.
게이트웨이 관리 화면에서 배포하는 방법은 게이트웨이 3.4.0 이상에서 씁니다.

PC에 정책 파일 두기게이트웨이에서 받기 (게이트웨이 3.4.0 이상)
정하는 곳운영체제마다 정해진 위치에 파일을 둡니다.관리자가 관리 화면의 관리 정책에서 조직 정책(JSON)을 저장합니다.
받는 PC파일을 둔 PC그 게이트웨이에 로그인한 PC
배포 도구Windows는 그룹 정책이나 Intune으로 배포합니다.게이트웨이가 배포합니다.
넣을 수 있는 키모든 관리 정책 키정해진 키만 (아래 표)

PC에 정책 파일 두기​

PC의 정책 파일 위치는 아래와 같습니다.
관리자만 쓸 수 있고 사용자는 읽을 수 있게 둡니다.
Windows의 C:\Program Files와 Linux의 /etc는 기본 권한이 그렇게 되어 있습니다.

운영체제경로
WindowsC:\Program Files\fortress\policy.json
macOS/Library/Application Support/fortress/policy.json
Linux/etc/fortress/policy.json

Windows 레지스트리는 읽지 않습니다.
파일에 넣는 항목은 페이지 끝 "자세히"에 있습니다.

주의

정책 파일이 있는데 JSON으로 읽히지 않으면 모든 도구 호출을 거부합니다.
배포한 뒤 fortress doctor로 꼭 확인합니다.

확인하는 법​

사용자 PC에서는 세 곳에서 봅니다.
웹 화면의 보안⁠·⁠감사, 터미널의 /audit, fortress doctor의 관리 정책 줄입니다.

PC에 정책 파일을 둔 경우​

2.6.1 화면에서는 아래처럼 보입니다.

보는 곳보이는 것
웹 화면 사이드바 보안⁠·⁠감사 › 정책⁠·⁠기록 칸관리자 줄에 정책 이름과 버전(about의 name, version). 아래 개인(로컬), 관리자 줄에 허용⁠·⁠묻기⁠·⁠거부 규칙 수
웹 화면 사이드바 사용자 지정 › 권한 탭정책에서 온 규칙에 관리 태그. 지우기(×) 버튼이 없습니다.
터미널 fortress doctor관리 정책 줄에 "파일"과 정책 파일 경로

게이트웨이 3.4.0 이상에서 배포하기​

게이트웨이를 3.4.0 이상으로 올리면 관리 화면에 관리 정책 메뉴가 생깁니다.
관리자가 이 메뉴에서 JSON 하나를 저장하면, 그 게이트웨이에 로그인한 Fortress AI 클라이언트가 받아 따릅니다.
조직에 정책은 하나이고 모든 사용자에게 같습니다.

저장과 삭제​

관리 정책 예: 샌드박스를 끌 수 없게 하고 권한 무시 모드를 막음
{
  "sandbox": { "enabled": true, "required": true },
  "disableBypassPermissionsMode": true,
  "permissions": { "deny": ["Read(./.env)", "Read(./secrets/**)"] },
  "about": { "name": "개발 보안 정책", "contact": "보안팀" }
}
  • 모르는 키나 틀린 타입이 하나라도 있으면 저장하지 않고 그 이유를 보입니다.
  • 셸 명령을 실행하는 설정(훅)은 넣을 수 없습니다.
  • 저장할 때마다 정책 버전이 1씩 오릅니다. 같은 내용을 다시 저장하면 버전은 그대로입니다.
  • 정책을 지우면 클라이언트는 다음 대화부터 자기 PC의 정책 파일만 따릅니다.
  • 저장과 지우기는 관리 화면의 감사 기록에 누가, 언제, 이전과 이후 본문과 함께 남습니다. 본문은 감사 기록 CSV의 detail 칸에 있습니다.

넣을 수 있는 키​

키값
permissions.allow, permissions.ask, permissions.deny, permissions.additionalDirectories문자열 배열
permissions.defaultMode"default", "acceptEdits", "plan", "dontAsk", "bypassPermissions" 가운데 하나
sandbox.enabled, sandbox.requiredtrue⁠·⁠false
sandbox.network.allowedDomains, sandbox.filesystem.denyRead, sandbox.filesystem.denyWrite문자열 배열
disableBypassPermissionsMode, allowManagedPermissionRulesOnly, redactInputtrue⁠·⁠false
packageMirrors이름과 http(s) 주소의 쌍
aboutname, version, contact 문자열

그 밖의 키는 PC의 정책 파일에서만 읽습니다.

  • 예: allowUnsandboxedCommands, strictAllowlist, commandMemoryLimit
주의

게이트웨이 정책은 PC 정책 파일과 같은 효력이 있습니다.
넓히는 키(permissions.allow 등)와 끄는 값(샌드박스 false, 권한 무시 모드)도 그대로 적용됩니다.
관리자 계정과 비밀번호를 정책 파일만큼 엄격하게 관리합니다.

둘 다 쓸 때의 우선순위​

  • PC 파일이 정한 키는 파일 값이 우선합니다. 규칙 목록도 같아서, 파일에 deny가 있으면 게이트웨이의 deny는 쓰지 않습니다.
  • 게이트웨이 정책은 파일이 정하지 않은 키만 채웁니다.
  • PC 파일에 managedGatewayUrl을 적어야 그 게이트웨이의 정책을 받습니다. 적지 않으면 그 PC는 파일만 따릅니다.
  • PC에 파일이 없으면 로그인한 게이트웨이의 정책을 받습니다.

중앙에서 바꾸고 싶은 키(규칙, 샌드박스 켜기)는 PC 파일에 두지 않습니다.
사용자가 절대 바꾸면 안 되는 값은 PC 파일에 둡니다.

policy.json (게이트웨이 정책도 받는 PC의 예)
{
  "managedGatewayUrl": "http://gw.corp.local:8080",
  "sandbox": { "allowUnsandboxedCommands": false },
  "allowUnsandboxedBypass": false
}
주의

게이트웨이 정책에는 서명이 없습니다.
파일이 비워 둔 키는 그 PC 사용자가 받아 둔 정책을 손으로 고치고 게이트웨이 접속을 막으면 바꿀 수 있습니다.

반드시 지켜야 하는 값은 위의 정해진 위치에 둔 PC 파일에 적습니다.
그 위치는 관리자만 쓸 수 있게 두어, 일반 사용자가 고치지 못하게 합니다.

정책을 받는 시점과 받지 못할 때​

로그인한 PC는 처음 대화를 열 때 게이트웨이에 정책을 묻고 최대 10초 기다립니다.
켜져 있는 동안에는 1시간마다 다시 받습니다.
바꾼 정책은 받은 뒤의 새 대화부터 적용되며, 켜져 있는 PC는 최대 1시간 걸립니다.

fortress를 다시 실행하면 그때 받습니다.
게이트웨이에 정책이 없으면(관리 정책 메뉴가 없는 3.3.0 포함) PC는 자기 정책 파일만 따르고, 대화는 그대로 시작합니다.

상황동작
게이트웨이가 꺼졌거나 답이 늦거나 혼잡할 때전에 받은 정책으로 시작하고 한 번 알립니다.
로그인이 거절됐을 때전에 받은 정책으로도 시작하지 않습니다. fortress login으로 다시 로그인합니다.
처음 로그인했는데 한 번도 받지 못했을 때대화를 시작하지 않고, 네트워크를 확인하거나 관리자에게 문의하라고 알립니다.
정책에 틀린 키가 있을 때그 키만 건너뛰고 알립니다.

받은 정책은 ~/.fortress/agent/gateway-policy.json에 둡니다.
로그아웃하거나 다른 게이트웨이로 로그인하면 지웁니다.

받았는지 확인하는 법​

사용자 PC의 보안⁠·⁠감사, /audit, fortress doctor에 아래 세 가지가 나옵니다.

  • 출처: 게이트웨이 주소와 버전
  • 정책을 받은 시각
  • 건너뛴 키

관리자는 관리 화면 관리 정책 메뉴의 아래 표를 봅니다.
사용자마다 클라이언트가 마지막 모델 호출 때 알린 값과 그 시각이 나옵니다.
값은 클라이언트 버전, 받은 정책, 샌드박스 상태(on⁠·⁠off⁠·⁠failed)입니다.

표시뜻
적용받은 정책이 지금 정책과 같습니다.
이전 정책받은 정책이 지금 정책과 다릅니다. 켜져 있는 PC는 1시간 안에 다시 받습니다.
모름상태를 알리지 않는 도구만 썼습니다.

이 표는 클라이언트가 스스로 알린 값이라 참고로만 봅니다.
이 값으로 호출을 막지는 않습니다.
허용⁠·⁠거부를 남기는 감사 로그는 여기에 모이지 않고 각 PC에 남습니다(감사 로그).

자세히: PC 정책 파일 예시와 항목

폐쇄망 기준의 예입니다.
주소와 이름은 조직에 맞게 바꿉니다.

policy.json
{
  "permissions": {
    "deny": ["Bash(curl *)", "Bash(wget *)", "Read(~/.ssh/**)"],
    "defaultMode": "default"
  },
  "sandbox": {
    "enabled": true,
    "required": true,
    "allowUnsandboxedCommands": false,
    "network": { "allowedDomains": ["nexus.corp.local", "git.corp.local"], "strictAllowlist": true }
  },
  "disableBypassPermissionsMode": true,
  "redactInput": true,
  "packageMirrors": {
    "npm": "http://nexus.corp.local/repository/npm/",
    "pip": "http://nexus.corp.local/repository/pypi/simple"
  },
  "commandMemoryLimit": "8G",
  "about": { "name": "보안팀 표준", "version": "v3", "contact": "sec@corp.local" }
}
항목뜻
permissions.deny거부할 도구와 대상. 어느 권한 모드에서도 적용됩니다.
permissions.defaultMode기본 권한 모드
sandbox.enabled샌드박스를 켭니다.
sandbox.required샌드박스 없이는 명령을 실행하지 않습니다.
sandbox.allowUnsandboxedCommandsfalse면 샌드박스 밖 재실행을 묻지 않고 막습니다.
sandbox.network.allowedDomains샌드박스 안 명령이 묻지 않고 접속하는 주소
sandbox.network.strictAllowlisttrue면 목록 밖 주소를 묻지 않고 거부합니다.
disableBypassPermissionsMode권한 무시 모드를 쓰지 못하게 합니다.
redactInput입력 가림을 켭니다.
packageMirrors사내 패키지 저장소 주소
commandMemoryLimit에이전트 명령이 함께 쓰는 메모리 상한. Linux에서만 적용됩니다.
about정책의 이름, 버전, 연락처. 이름과 버전은 사용자의 보안⁠·⁠감사 화면 정책⁠·⁠기록 칸에 보입니다.
managedGatewayUrl이 PC가 정책을 받을 게이트웨이 주소(게이트웨이 3.4.0 이상)
  • packageMirrors의 주소는 allowedDomains에도 넣습니다. 넣지 않으면 접속할 때 묻고, strictAllowlist가 켜져 있으면 거부합니다.
  • 사내 저장소 주소는 IP 주소가 아닌 호스트 이름으로 씁니다. IP 주소로 쓰면 샌드박스 안 명령이 접속하지 못합니다.
  • 정책으로 정해진 규칙은 사용자의 사용자 지정 화면에서 보기만 할 수 있습니다.
  • 환경 변수 AXF_MANAGED_POLICY는 사용자가 값을 바꿀 수 있어 강제 수단이 아닙니다. 위 위치에 파일이 있으면 그 파일만 적용됩니다.

다음에 볼 글

관리 화면 둘러보기게이트웨이 관리 화면의 메뉴, 관리자와 사용자의 차이, 계정 추가·비밀번호·사용 중지와 다시 사용, 사용량과 호출 기록, API 키, 로그인한 기기, 감사 기록, 기록 보관 기간입니다.감사 로그에이전트가 도구를 쓸 때 허용·거부한 감사 로그가 어디에 어떤 내용으로 남는지, 화면에서 골라 보고 파일로 받는 방법, 관리 화면의 감사 기록과 다른 점입니다.권한 규칙허용, 물어봄, 거부 규칙을 쓰는 문법과 평가 순서, PowerShell 규칙, 거부 규칙과 샌드박스의 관계, 규칙이 막지 못하는 경우입니다.
