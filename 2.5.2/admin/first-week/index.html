Fortress AI 2.5.2 기준

이 쪽을 읽으면 Fortress AI를 들인 첫 주에 무엇을 어떤 순서로 점검할지 정할 수 있습니다.

항목마다 자세한 순서가 있는 쪽으로 연결합니다.
설치와 정책 배포 순서는 동봉 문서를 기준으로 적었습니다.

1. 설치 방식을 정합니다​

  • 개발자 PC에 설치할지, 공용 개발 서버에 한 번 설치할지 정합니다. 설치 방식과 점검
  • 게이트웨이에서 받을 수 없는 환경이면 묶음 파일을 반입해 설치 스크립트로 설치합니다. 묶음으로 설치하기
  • 사용자에게 안내할 게이트웨이 주소를 정합니다. 설치에 관리자 권한은 필요하지 않습니다.

2. 정책 파일을 배포합니다​

  • 정책 파일을 운영체제별 위치에 둡니다. 관리자만 쓸 수 있고 사용자는 읽을 수 있게 둡니다. 관리자 정책
  • Windows에서는 그룹 정책이나 Intune으로 파일을 배포합니다.
  • about에 정책의 이름과 판을 적습니다. 사용자의 보안⁠·⁠감사 화면에 정책 이름, 판, 지문이 보여 적용 여부를 확인할 수 있습니다.
  • 사내 패키지 저장소 주소는 packageMirrors와 allowedDomains에 함께 넣고, IP 주소가 아닌 호스트 이름으로 씁니다.

3. Windows PC의 샌드박스를 켭니다​

  • Windows에서는 샌드박스가 기본으로 꺼져 있습니다. PC마다 관리자 권한으로 fortress windows-install을 한 번 실행합니다.
  • 정책 파일에서 sandbox.enabled를 켭니다. Windows 샌드박스 켜기

4. 설치한 PC를 점검합니다​

  • fortress doctor로 로그인, 모델 서버, 게이트웨이, 권한 규칙, 샌드박스를 점검합니다.
  • 정책 파일이 JSON으로 읽히지 않으면 모든 도구 호출을 거부합니다. 배포한 뒤 fortress doctor로 확인합니다.
  • 사이드바의 보안⁠·⁠감사에서 전송 대상이 "이 서버만"으로, 외부 버전 확인⁠·⁠원격 측정⁠·⁠자동 설치⁠·⁠세션 업로드가 "꺼짐"으로 표시되는지 봅니다.
  • 샌드박스 칸에서 상태와 네트워크 허용 범위를 봅니다.

5. 사용자에게 안내합니다​

  • 설치하고 첫 요청 보내기를 보냅니다.
  • 업무 담당자에게는 업무별로 해 보기를 함께 보냅니다.
  • 결과는 담당자가 확인하고 쓴다는 점을 알립니다. 에이전트가 읽은 파일과 실행한 명령은 타임라인에서 차례로 볼 수 있습니다.
  • 개인정보가 든 파일은 작업 폴더에 두지 않거나 권한 규칙으로 읽기를 막도록 알립니다. 입력 가림은 입력창에 쓴 글에만 적용됩니다.

6. 첫 주 끝에 기록을 봅니다​

  • 보안⁠·⁠감사에서 거부만 골라 무엇이 막혔는지 봅니다. 거부 사유는 결과 칸에 표시됩니다.
  • 필요하면 CSV 내보내기로 받습니다. 지금 화면에 보이는 기록만 내보냅니다.
  • 여러 PC의 기록을 모으려면 각 PC의 기록 파일을 수집합니다. 중앙에서 모으는 기능은 없습니다. 감사 기록
