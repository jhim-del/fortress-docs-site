결함을 고치고 장애 처리 보고서 쓰기

Fortress AI 2.5.2 기준

이럴 때 봅니다

  • 운영 중인 시스템에 오류가 접수돼 원인 찾기와 수정을 맡기고 싶을 때
  • 고친 내용으로 발주처에 낼 장애 처리 보고서 초안이 필요할 때
  • 고친 코드와 보고서 내용이 맞는지 확인하고 싶을 때
넣는 것받는 것걸린 시간
시스템 소스 폴더, 접수된 증상고친 코드, 추가한 테스트, docs/장애처리보고서.md2~3분 (가상 자료로 실행)

1. 소스 폴더를 고르고 요청문을 보냅니다​

새로 생성을 누르면 "어디서 작업할까요?"가 열립니다.
시스템 소스가 있는 폴더를 (에이전트가 읽고 고칠 파일이 있는 폴더)로 고릅니다.
아래 요청문을 입력창에 붙여 넣고 보냅니다.
접수 내용과 파일 이름은 우리 상황에 맞게 고쳐 쓰면 됩니다.

이렇게 보이면 된 것 요청이 대화에 올라가고, 에이전트가 소스 파일을 읽기 시작합니다.

2. 확인 창을 읽고 허용합니다​

파일을 고치거나 테스트를 실행하기 전에 (실행 전에 묻는 확인 창)가 뜹니다.
무엇을 고치고 어떤 명령을 실행하려는지 읽고 허용합니다.
몇 번 묻는지는 (실행 전에 어디까지 묻는지 정하는 설정)에 따라 다릅니다.

이렇게 보이면 된 것 답에 전체 테스트를 실행한 결과가 나오고, 모두 통과했다고 적혀 있습니다.

3. 보고서 파일을 엽니다​

작업이 끝나면 오른쪽 파일 칸에서 docs/장애처리보고서.md를 엽니다.
요청한 다섯 항목(접수 내용, 원인, 조치 내용, 테스트 결과, 재발 방지 방안)이 차례로 있는지 봅니다.

이렇게 보이면 된 것 보고서에 다섯 항목이 모두 있고, "테스트 결과"에 방금 실행한 결과가 들어 있습니다.

4. 바뀐 코드와 보고서를 맞춰 봅니다​

오른쪽 변경 사항 칸을 열면 이 (대화 하나)에서 바뀐 줄이 보입니다.
보고서의 "조치 내용"에 적힌 수정과 실제로 바뀐 줄이 같은지 맞춰 봅니다.
테스트는 담당자가 직접 한 번 더 실행해 봅니다.

이렇게 보이면 된 것 보고서의 조치 내용에 적힌 수정이 변경 사항 칸에 그대로 있습니다.

주의

보고서는 초안입니다.
제출하기 전에 담당자가 내용을 검토합니다.

마음에 들지 않으면​

  • 수정이 마음에 들지 않으면 (이전 시점으로 되돌리기)로 되돌립니다. 명령으로 바뀐 파일은 되돌려지지 않습니다. 결과 확인하고 되돌리기에 범위가 있습니다.
  • 보고서를 한글 문서로 내려면 결과를 한글 문서로 저장하기를 봅니다.

막히면

  • 작업이 멈춰 있습니다확인할 것 보기
  • 작업이 거부됩니다확인할 것 보기
  • 답은 있는데 결과 파일이 없습니다확인할 것 보기
