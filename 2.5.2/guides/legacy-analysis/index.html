문서 없는 시스템의 현행 분석서 만들기

Fortress AI 2.5.2 기준

이 쪽을 읽으면 문서가 거의 없는 시스템의 소스를 읽혀 근거 파일 경로가 붙은 현행 분석서를 받을 수 있습니다.

구축사가 철수해 문서가 README 하나뿐인 시스템을 인수받았을 때 쓰는 방법입니다.
소스 폴더를 읽혀 현행 분석서를 받습니다.

넣는 것받는 것실제 걸린 시간
시스템 소스 폴더docs/현행분석서.md약 9분

요청문​

아래 글을 입력창에 붙여 넣습니다.
시스템 설명과 결과 파일 이름은 상황에 맞게 고칩니다.

요청문
이 시스템은 구축사가 철수해서 문서가 README 하나뿐인 민원 포털이야.
우리가 유지보수를 인수받았어.

현행 분석서를 docs/현행분석서.md 로 만들어줘.

꼭 들어갈 것
1. 모듈 목록과 공통 구조(계층)
2. 민원 접수 → 담당자 배정 → 문자 알림 처리 흐름과 예외 규칙
3. README 설명과 실제 설정이 다른 곳
4. 보안 취약 의심 지점
5. 어디서도 호출하지 않는 코드

항목마다 근거 파일 경로를 적어줘.

순서​

1. 소스 폴더를 고르고 요청합니다​

새로 생성을 누르고 "어디서 작업할까요?"에서 시스템 소스가 있는 폴더를 고릅니다.
입력창에 요청문을 붙여 넣고 보냅니다.

2. 확인 창을 읽고 허용합니다​

실행 확인을 묻는 창이 뜨면 내용을 읽고 허용합니다.
권한 모드에 따라 묻는 횟수가 다릅니다.

3. 분석서를 엽니다​

작업이 끝나면 docs/현행분석서.md를 엽니다.
요청한 다섯 항목이 모두 들어 있는지 봅니다.

4. 근거 경로를 열어 대조합니다​

항목마다 근거 파일 경로가 붙어 있는지 봅니다.
근거 경로 두세 곳을 직접 열어 내용이 맞는지 대조합니다.

결과를 확인하는 법​

  • 요청한 다섯 항목이 모두 들어 있는지 봅니다.
  • 항목마다 근거 파일 경로가 붙어 있는지 봅니다.
  • 근거 경로 두세 곳을 직접 열어 내용이 맞는지 대조합니다.
  • "추정"이라고 표시된 내용은 담당자가 따로 확인합니다.
참고

같은 종류의 시험(2.4.0)에서는 소스에 숨겨 둔 문제 15개 가운데 14개를 정확히 찾았고 1개는 부분적으로 찾았습니다.
시험에 쓴 자료는 가상 시스템입니다.

전체 과정 영상​

알아 둘 점​

  • 분석 범위가 넓으면 시간이 길어집니다. 모듈 단위로 나눠 요청하면 결과를 확인하기 쉽습니다.
  • 분석서는 초안입니다. 운영에 반영하기 전에 담당자가 검토합니다.

다음에 볼 글

운영 DB로 DB 구조 정의서 만들기운영 DB 파일을 읽혀 테이블, 관계, 트리거와 뷰를 정리한 DB 구조 정의서를 Word 파일로 받는 과정입니다.코드 보안 검토하기작업 폴더의 코드를 보안 관점에서 검토하고, 발견 사항을 분류 보드에서 정리해 보고서로 내보내는 과정입니다.결과 확인하고 되돌리기에이전트가 한 일을 타임라인으로 보고, 바뀐 파일과 만든 파일을 확인하고, 마음에 들지 않으면 이전 시점으로 되감는 방법입니다.
