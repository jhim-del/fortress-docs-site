권한 규칙

Fortress AI 2.6.1 기준

이럴 때 봅니다

  • 자주 쓰는 명령은 묻지 않게 하고, 위험한 명령은 막고 싶을 때
  • Windows에서 PowerShell 명령을 허용하거나 막아야 할 때
  • 거부 규칙이 스크립트로 읽는 것까지 막는지 알고 싶을 때

권한 규칙은 특정 도구와 대상을 허용하거나, 묻게 하거나, 거부하는 규칙입니다.
정책 파일의 permissions.allow, ask, deny에 적습니다.

규칙은 명령 문자열을 비교하는 안전망입니다.
어떤 형태로 써도 막아야 하는 것은 (운영체제 수준의 격리)가 막습니다(경계와 안전망).

무엇을 정하나​

규칙동작
허용묻지 않고 실행합니다.
묻기실행할 때마다 확인을 묻습니다.
거부실행하지 않습니다.

규칙에 맞은 판단은 모두 에 남습니다.
어떤 규칙으로 허용되거나 거부되었는지는 감사 로그에서 봅니다.

화면에서 규칙 추가하기​

사이드바의 사용자 지정에서 권한 탭을 엽니다.

  1. 규칙 종류를 고릅니다. 허용은 묻지 않고 실행, 묻기는 매번 확인, 거부는 실행하지 않습니다.
  2. 규칙을 입력합니다. 예: Bash(npm test), Read(src/**)
  3. 적용 범위를 고르고 추가를 누릅니다.

네트워크에는 샌드박스 안의 명령이 묻지 않고 접속할 수 있는 주소가 보입니다.
관리자 정책과 프로젝트 파일의 규칙은 보기만 할 수 있습니다.

평가 순서​

규칙은 어디에 적혀 있든 거부 → 물어봄 → 허용 순서로 평가합니다.
어느 파일에서든 거부 규칙이 하나라도 맞으면 거부됩니다.

문법​

규칙뜻
Bash모든 명령
Bash(npm run test)정확히 이 명령
Bash(npm run *)이렇게 시작하는 명령. npm run은 맞고 npm runx는 맞지 않습니다.
PowerShell(Get-ChildItem *)Windows PowerShell 도구의 명령. 아래 PowerShell 규칙을 봅니다.
Read(./src/**)경로를 읽는 것
Edit(/docs/**)경로를 고치는 것. Write(...), MultiEdit(...)도 같습니다.
Grep, Find, LS찾기⁠·⁠목록 도구 전체. 이 도구들이 읽는 경로는 Read 규칙이 다룹니다.
Agent(explore)서브에이전트 하나. Task(...), Subagent(...)도 같습니다.
mcp__server, mcp__server__tool커넥터의 도구

경로 쓰는 법​

시작뜻예
//절대 경로Read(//C:/자료/**)
~/홈 폴더Read(~/.ssh/**)
/ 또는 ./프로젝트 루트Edit(/docs/**)
슬래시 없음모든 깊이Read(.env)

Windows의 절대 경로는 //C:/폴더/**처럼 씁니다.
\도 /처럼 폴더를 나누는 기호로 읽습니다.

예시​

policy.json의 일부
{
  "permissions": {
    "allow": ["Bash(npm run test)", "Read(./src/**)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Bash(curl *)", "Bash(wget *)", "Read(~/.ssh/**)"]
  }
}

PowerShell 규칙 (Windows)​

Windows에서 PowerShell 도구를 켜면 쓰는 규칙입니다.
PowerShell 명령은 PowerShell(...) 규칙으로 정합니다.

규칙맞는 명령
PowerShell모든 PowerShell 명령
PowerShell(git status)정확히 이 명령
PowerShell(Get-ChildItem *)Get-ChildItem으로 시작하는 명령. 별칭 ls, dir, gci에도 맞습니다.
PowerShell(Remove-Item *)Remove-Item과 별칭 rm, del, ri
  • 대소문자를 가리지 않습니다.
  • 한 줄에 명령이 여러 개면 명령마다 맞춰 봅니다. 모든 명령이 허용되어야 묻지 않습니다. 예를 들어 PowerShell(git *)은 git status; Remove-Item x의 Remove-Item까지 허용하지 않습니다.
  • Get-ChildItem, Get-Content, Select-String 같은 읽기 명령은 규칙이 없어도 묻지 않습니다.
  • 변수나 스크립트 블록처럼 읽어 내지 못한 줄은 어느 모드에서든 묻습니다.
주의

Bash(...) 거부 규칙은 PowerShell 도구를 막지 않습니다.
Windows에서 막아야 할 명령은 PowerShell(...) 거부 규칙에도 넣습니다.

PowerShell 도구를 아예 끄려면 관리자 정책에 "powershellTool": false를 둡니다.
샌드박스를 MXC 방식으로 켠 PC는 PowerShell 도구만 쓰므로 PowerShell(...) 거부 규칙만 듣습니다.

거부 규칙과 샌드박스 (macOS⁠·⁠Linux)​

macOS와 Linux에서 샌드박스가 켜져 있으면 Read⁠·⁠Edit 거부 규칙이 가리키는 경로를 샌드박스의 금지 목록에도 넣습니다.
이 경로는 cat 대신 스크립트로 읽어도 막힙니다.

거부 규칙샌드박스에서 막는 것
Read(...)읽기와 쓰기 모두. 읽지 못할 파일을 덮어쓰지도 못하게 합니다.
Edit(...)쓰기만

작업 폴더의 정책 파일에 적은 거부 규칙은 를 한 폴더에서만 샌드박스에 넣습니다.
샌드박스 금지 목록에 넣지 못한 규칙은 문자열 비교(안전망)로만 막습니다.

공용 서버에서 다른 사용자의 홈 폴더(macOS /Users 아래, Linux /home 아래)도 샌드박스가 읽지 못하게 막습니다.
이 밖의 경로를 어떤 방법으로도 읽지 못하게 하려면 sandbox.filesystem.denyRead에 적습니다.
내 정책이나 관리자 정책에 절대 경로나 ~로 씁니다.

Windows 샌드박스는 Windows 샌드박스 켜기를 봅니다.

자세히: 샌드박스 금지 목록에 들어가는 규칙 형식
규칙 형식macOSLinux
경로 그대로(Read(~/.config/app/token)), 폴더 전체(Read(./secrets/**))넣음넣음. 명령을 시작할 때 없는 경로는 넣지 않습니다.
그 밖의 와일드카드(Read(./keys/*.pem))넣음읽기만 넣음. 명령을 시작할 때 있는 파일만 막습니다.
**가 든 것(Read(**/*.key)), 이름만 쓴 것(Read(*.pem))넣음넣지 않음
Edit(...)의 와일드카드넣음넣지 않음
중괄호(Read(./{a,b}/**))항목마다 풀어 넣음항목마다 풀어 넣음
작업 폴더나 그 위 폴더를 통째로 덮는 규칙(Read(./**), Read(~/*))넣지 않음넣지 않음

작업 폴더를 덮는 규칙을 넣지 않는 것은 샌드박스가 그 폴더를 읽고 써야 명령이 돌기 때문입니다.

명령을 판단하는 방식​

  • &&, |, ;로 이어진 명령은 나눠서 하나씩 판단합니다. 하나라도 거부되면 전체를 거부합니다.
  • timeout, env, sh -c 같은 감싸는 명령은 벗겨서 안쪽 명령을 봅니다.
  • 문법으로 읽어 내지 못한 줄은 어느 권한 모드에서든 묻습니다.
  • 승인 창의 "다시 묻지 않기"가 제안하는 규칙은 승인한 명령보다 넓지 않게 잡습니다.

규칙의 한계​

주의

거부 규칙은 명령 문자열을 비교하는 방식입니다.
따옴표를 쪼개는 식으로 모양을 바꾼 명령까지 모두 막지는 못합니다.
외부 접속과 작업 폴더 밖 쓰기를 명령 모양과 상관없이 막으려면 샌드박스를 함께 켭니다.

다음에 볼 글

샌드박스샌드박스가 에이전트의 명령에서 무엇을 막고 무엇은 다른 장치에 맡기는지, 켜져 있는지 확인하는 법입니다.관리자 정책조직 공통 규칙을 PC의 정책 파일로 배포하는 방법, 게이트웨이 3.4.0 이상의 관리 정책 화면, 둘이 겹칠 때의 우선순위, 받았는지 확인하는 법입니다.내 방식으로 맞추기지침 파일, 스킬, 서브에이전트, 명령, 커넥터, PowerShell 도구, 권한 규칙으로 Fortress AI가 일하는 방식을 조직과 업무에 맞추는 방법입니다.
