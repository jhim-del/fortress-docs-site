내 방식으로 맞추기

Fortress AI 2.6.1 기준

이럴 때 봅니다

  • 요청할 때마다 같은 규칙(날짜 형식, 문체, 테스트)을 다시 말하고 있을 때
  • 팀이 쓰는 절차나 사내 도구를 에이전트에 붙이고 싶을 때
  • 다른 AI 코딩 도구에서 쓰던 설정을 옮겨 오고 싶을 때

맞춘 것은 모두 사이드바의 사용자 지정에 모여 보입니다.
처음에는 작업 폴더에 을 두는 것부터 해 봅니다.

1. 사용자 지정 화면을 엽니다​

사이드바의 사용자 지정을 누릅니다.

탭내용
스킬자주 하는 일의 절차를 묶어 둔 것
커넥터외부 도구와 연결하는 MCP 커넥터. 비어 있으면 넣을 파일 위치와 적는 예가 보입니다.
에이전트일을 나눠 맡는 서브에이전트. 처음부터 explore(코드 탐색, 읽기 전용)와 general(범용)이 "기본 제공"으로 들어 있습니다.
명령/이름으로 부르는 프롬프트 명령. 비어 있으면 넣을 파일 위치(.fortress/prompts/이름.md)가 보입니다.
메모리지금 불러온 지침 파일
권한지금 권한 모드와 허용, 묻기, 거부 규칙, 샌드박스의 네트워크 허용 주소. 추가하고 지울 수 있습니다.

이렇게 보이면 된 것 위쪽에 스킬, 커넥터, 에이전트, 명령, 메모리, 권한 탭이 보입니다.

관리자 정책과 프로젝트 파일로 정해진 항목은 이 화면에서 보기만 할 수 있습니다.
권한 탭에서 관리자 정책의 규칙에는 관리 태그가 붙고, 내가 넣은 규칙에는 로컬 태그와 지우기(×) 버튼이 붙습니다.

2. 지침 파일을 둡니다​

작업 폴더에 FORTRESS.md 파일을 두면 그 폴더의 모든 세션에서 에이전트가 내용을 지침으로 읽습니다.
여러 AI 도구가 같이 읽는 AGENTS.md도 읽습니다.

FORTRESS.md 예
- 변수 이름은 영어로, 주석은 한국어로 쓴다.
- 코드를 고치면 테스트를 함께 고친다.
- 보고서의 날짜는 2026. 11. 20. 형식으로 쓴다.

이렇게 보이면 된 것 사용자 지정의 메모리 탭에 파일 이름과 경로, 대략의 토큰 수가 보입니다.

지침 파일은 아래 순서로 들어가고, 작업 폴더에 가까운 것이 더 구체적인 지침이 됩니다.

순서위치적용 범위
1내 설정 폴더(~/.fortress/agent/)의 AGENTS.md, FORTRESS.md내 모든 프로젝트
2맨 위 폴더부터 작업 폴더까지 폴더마다 있는 AGENTS.md, FORTRESS.md그 폴더 아래
3작업 폴더의 .fortress/rules/신뢰한 폴더에서만

CLAUDE.md는 읽지 않습니다.
옮기려면 아래 다른 도구의 설정 가져오기를 씁니다.

지침 파일의 내용은 세션을 시작할 때 모델 서버로 전달됩니다.
전달되는 범위는 서버로 가는 데이터에서 봅니다.

3. 스킬, 서브에이전트, 명령을 더합니다​

자주 하는 일의 절차는 로 둡니다.
나눠 맡길 역할은 로, 자주 쓰는 요청은 프롬프트 명령으로 둡니다.
내 것은 내 설정 폴더에, 팀이 같이 쓸 것은 작업 폴더의 .fortress/ 아래에 둡니다.

무엇내 설정 폴더(~/.fortress/agent/)작업 폴더
스킬skills/.fortress/skills/
서브에이전트agents/*.md.fortress/agents/
프롬프트 명령prompts/.fortress/prompts/<이름>.md
커넥터mcp.json.fortress/mcp.json

작업 폴더에 둔 스킬, 서브에이전트, 명령은 를 한 폴더에서만 적용됩니다.
넣은 것은 사용자 지정의 해당 탭에서 확인합니다.
서브에이전트마다 허용하거나 막으려면 권한 규칙 Agent(이름)을 씁니다.

4. 커넥터로 사내 도구를 연결합니다​

(MCP 서버)는 에이전트가 사내 시스템이나 다른 도구를 쓰게 하는 연결입니다.
mcp.json에 적은 커넥터는 사용자 지정의 커넥터 탭과 대화 화면 오른쪽의 커넥터 칸에 보입니다.
입력창의 + 메뉴에서도 고릅니다.

커넥터의 도구도 권한 규칙으로 허용하거나 막습니다.
규칙은 mcp__서버이름, mcp__서버이름__도구이름 형식입니다.

5. 다른 도구의 설정 가져오기​

작업 폴더에 Claude Code 설정이 있으면 한 번에 옮겨 옵니다.
웹에서는 새 세션 화면에 뜨는 가져오기 알림을, 입력창에서는 /migrate를 씁니다.

원래 파일옮겨지는 곳
CLAUDE.mdFORTRESS.md
.claude/skills/<이름>/.fortress/skills/<이름>/
.claude/commands/ 의 명령.fortress/prompts/<이름>.md
.claude/agents/ 의 에이전트.fortress/agents/<이름>.md
.claude/rules/.fortress/rules/

이렇게 보이면 된 것 작업 폴더에 FORTRESS.md와 .fortress/ 아래 파일이 생기고, 원래 파일은 그대로 남습니다.

이미 있는 파일은 덮어쓰지 않습니다.
.mcp.json, 훅과 권한 규칙, CLAUDE.local.md는 가져오지 않습니다.

6. Windows에서 PowerShell 도구를 켭니다​

Windows에서는 명령 도구(Git Bash) 옆에 PowerShell 도구를 둘 수 있습니다.
내 정책 파일(~/.fortress/agent/policy.json)이나 관리자 정책에 아래 한 줄을 넣습니다.

policy.json의 일부
{ "powershellTool": true }

이렇게 보이면 된 것 새로 연 세션에서 에이전트가 PowerShell로 명령을 실행합니다.

값동작
true켭니다.
false끕니다.
적지 않음Git Bash가 없는 PC에서만 켭니다. Windows 설치 패키지는 Git Bash를 함께 깔기 때문에 패키지로 설치한 PC에서는 꺼져 있습니다.
  • 새로 여는 세션부터 적용됩니다.
  • 관리자 정책의 값이 우선합니다. 작업 폴더의 .fortress/policy.json은 이 값을 읽지 않습니다.
  • PowerShell 7이 있으면 그것을, 없으면 Windows PowerShell 5.1을 씁니다.
  • Get-ChildItem, Get-Content, Select-String 같은 읽기 명령은 묻지 않습니다. 변수나 스크립트 블록처럼 읽어 내지 못한 줄은 어느 모드에서든 묻습니다.
  • macOS와 Linux에서는 켜지지 않습니다.
주의

Bash(...) 거부 규칙은 PowerShell 도구를 막지 않습니다.
PowerShell 명령을 막으려면 PowerShell(...) 거부 규칙을 씁니다.

PowerShell 도구를 아예 끄려면 "powershellTool": false로 둡니다.
규칙 쓰는 법은 권한 규칙에 있습니다.

7. 권한 규칙을 더합니다​

권한 탭에서 허용, 묻기, 거부 규칙을 추가합니다.
규칙을 쓰는 법은 권한 규칙에서 봅니다.

다음에 볼 글

권한 규칙허용, 물어봄, 거부 규칙을 쓰는 문법과 평가 순서, PowerShell 규칙, 거부 규칙과 샌드박스의 관계, 규칙이 막지 못하는 경우입니다.설정과 화면 맞추기웹 화면의 설정을 여는 법과 일곱 탭의 구성, 새 세션의 권한 모드·알림·야간 큐 시간·화면 모양·로그인·버전 번호를 보고 바꾸는 곳입니다.컨텍스트, 모델, 사용 현황에이전트가 한 번에 참고하는 양을 보고 컨텍스트를 압축하는 법, 모델과 노력 수준을 고르는 곳, 모델 서버 상태와 답 하나·기간별 사용량을 보는 법입니다.
