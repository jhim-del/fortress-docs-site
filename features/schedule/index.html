예약과 반복 실행

Fortress AI 2.6.1 기준

이럴 때 봅니다

  • 매일 같은 시각에 보고서나 점검을 맡겨 두고 싶을 때
  • 모델 서버가 붐벼서 요청을 밤으로 미루고 싶을 때
  • 오래 걸리는 명령을 실행하는 동안 대화를 이어 가고 싶을 때
하려는 일쓰는 것
정한 시각에 실행예약 작업
붐빌 때 밤으로 미루기야간 큐
오래 걸리는 명령을 대화를 막지 않고 실행백그라운드 작업
같은 요청을 일정한 간격으로 다시 실행반복 실행

1. 예약 작업을 만듭니다​

(정한 시각에 실행하도록 맡겨 둔 일)은 대화에서 말로 요청해 만듭니다.
한 번만 실행하거나 일정에 따라 반복하게 할 수 있습니다.

요청 예
평일 9시마다 어제 들어온 오류 로그를 요약해줘.

에이전트가 예약을 만들거나 고칠 때는 실행 확인을 묻습니다.
이 확인에는 "다시 묻지 않기"가 없고, 내용을 읽고 허용하면 예약이 등록됩니다.

이렇게 보이면 된 것 사이드바의 예약됨 목록에 새 예약이 일정과 함께 보입니다.

프로젝트에 속하지 않은 세션에서도 예약을 만듭니다.

2. 예약됨에서 관리합니다​

사이드바의 예약됨을 누르면 프로젝트 안팎의 예약 작업이 한곳에 보입니다.
예약마다 일정, 폴더나 프로젝트, 다음 실행 시각, 지난 실행의 결과(실패, 건너뜀, 놓친 실행)가 보입니다.

  • 켜기 스위치로 켜고 끕니다.
  • 줄 오른쪽 ⋮ 메뉴에서 지금 실행, 지난 실행 보기, 삭제를 고릅니다.
  • 지난 실행 보기를 누르면 그 실행이 남긴 대화가 열립니다.

일정을 고칠 때는 대화에서 요청합니다.

3. 실행되는 조건을 확인합니다​

상황동작
Fortress 웹이 켜져 있음정한 시각에 실행합니다. 브라우저 창은 닫아도 됩니다.
Fortress 웹이 꺼져 있었거나 PC가 잠자기 중이었음다시 열 때 놓친 실행을 한 번 실행합니다. 최근 7일 안의 것만 해당합니다.
실행 중 승인이 필요함해당 대화에서 승인을 기다립니다.
터미널 화면만 켜져 있음실행하지 않습니다.
주의

승인이 필요한 일은 사람이 허용할 때까지 멈춰 있습니다.
사람이 없는 시간에 끝나야 하는 일은 승인 없이 할 수 있는 범위로 요청합니다.

4. 붐빌 때는 밤으로 미룹니다​

모델 서버에 대기 요청이 많으면 입력창 아래에 붐빔 안내와 "밤에 실행"이 보입니다.
"밤에 실행"을 고르면 요청이 야간 큐(밤사이 처리할 요청 목록)에 들어갑니다.
입력창 아래의 점은 모델 서버의 실행⁠·⁠대기 요청 상태를 보여 줍니다.

야간 큐가 실행되는 시간은 설정 › 일반 › 야간 큐의 실행 시간대에서 정합니다.
처음 값은 22:00~07:00이고, 자정을 넘기는 시간대로 둘 수 있습니다.
큐에 넣은 요청은 이 시간 안에 서버가 한가할 때 하나씩 실행됩니다.

요령

야간 큐의 실행은 지켜보는 사람이 없어 묻지 못합니다.
허용 목록 밖 주소에 접속하거나 샌드박스 밖에서 다시 실행하는 일은 묻지 않고 거부됩니다.
반복 실행(/loop)도 만들지 않습니다.

밤에 맡길 요청은 확인 없이 끝낼 수 있는 일로 고릅니다.

5. 오래 걸리는 명령은 백그라운드로 보냅니다​

오래 걸리는 명령은 백그라운드에서 실행하고 대화를 이어 갑니다.

방법동작
Ctrl+B실행 중인 명령을 그 자리에서 백그라운드로 옮기고 대화를 이어 갑니다.
시간 제한 초과명령이 기본 2분을 넘기면 멈추지 않고 백그라운드로 옮깁니다.
에이전트의 판단에이전트가 오래 걸릴 명령을 처음부터 백그라운드로 실행합니다.

이렇게 보이면 된 것 오른쪽 칸의 백그라운드 작업에 작업이 보이고, 에이전트는 다음 일을 이어 갑니다.

출력 보고 멈추기​

하려는 일방법
출력 보기오른쪽 칸의 백그라운드 작업에서 작업을 골라 출력을 봅니다.
멈추기같은 칸에서 중지합니다. 입력창에서는 /tasks stop <id>로 멈춥니다.
목록 보기/tasks로 이 세션의 백그라운드 작업 목록을 봅니다.

작업이 끝나면 대화 안에 안내 한 줄이 남고, 에이전트가 결과를 이어서 처리합니다.
알림을 놓쳐도 에이전트가 작업마다 상태, 종료 코드, 실행 시간, 출력 파일을 다시 찾아 결과를 이어 받습니다.
웹 화면과 터미널 화면에서 사람이 보는 세션은 명령 작업에 시간 제한이 없습니다.

6. 같은 요청을 반복 실행합니다​

/loop는 같은 요청을 이 세션에 일정한 간격으로 다시 넣습니다.

예
/loop 30m 빌드 상태를 확인하고 실패했으면 원인을 알려줘.

이렇게 보이면 된 것 보낸 즉시 한 번 실행되고, 그 뒤 간격마다 같은 요청이 대화에 들어옵니다.

항목내용
간격1분에서 24시간 사이. 만든 시각부터 셉니다.
일하는 중에 때가 되면하던 일이 끝난 뒤에 한 번 실행합니다. 그 사이 놓친 횟수를 따라 하지는 않습니다.
끝나는 때멈추거나, 한 번만 실행하게 했거나, 7일이 지나면 끝납니다.
보기와 멈추기/loop만 입력하면 목록, /loop stop <id>로 멈춥니다. /tasks와 백그라운드 작업 칸에도 보입니다.
세션을 닫았다 열면아직 끝나지 않은 반복이 다시 이어집니다. 닫혀 있던 동안 놓친 실행은 따라 하지 않습니다.

사람이 입력한 /loop는 묻지 않습니다.
에이전트가 반복을 만들 때는 묻습니다.
포크한 세션은 반복을 가져가지 않습니다.

알아 둘 점​

  • 백그라운드 명령도 일반 명령과 같은 권한 규칙과 샌드박스를 적용받습니다.
  • 세션을 닫으면 남은 백그라운드 작업은 모두 멈춥니다.
  • 명령이 뒤에 남긴 프로세스(예: npm run dev &)가 출력을 쥐고 있으면 작업은 계속 실행 중으로 보입니다. 출력을 닫고 따로 실행되는 프로세스는 따라가지 않습니다.
  • 한 세션에서 백그라운드로 동시에 실행되는 서브에이전트는 4개까지입니다.
  • Esc로 응답을 멈춰도 백그라운드 서브에이전트는 멈추지 않습니다. /tasks에서 따로 멈춥니다.
