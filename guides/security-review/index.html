코드 보안 검토하기

Fortress AI 2.6.1 기준

이럴 때 봅니다

  • 고친 코드를 커밋하기 전에 보안 문제가 없는지 점검하고 싶을 때
  • 물려받은 소스에 먼저 고쳐야 할 문제가 있는지 보고 싶을 때
  • 찾은 문제를 파일과 줄 번호로 받아 하나씩 고치고 싶을 때
입력 자료결과물
검토할 코드가 있는 작업 폴더발견 사항을 정리한 답 글, 답 끝의 분류 보드

요청문 대신 명령 /security-review 하나를 보냅니다.
검토 대상은 아직 커밋하지 않은 변경입니다.
커밋하지 않은 변경이 없으면 마지막 커밋 전체를 검토하고, 무엇을 검토했는지 답 첫머리에 적습니다.

1. 검토를 요청합니다​

예시 자료 내려받기10KB보안 문제 네 가지를 넣어 둔 예시 쇼핑몰 소스입니다. 쓰는 법

새로 생성을 누르고 검토할 폴더를 (에이전트가 읽고 고치는 폴더)로 고릅니다.
입력창에 아래 명령을 입력하고 보냅니다.

명령
/security-review

이렇게 보이면 된 것 보낸 명령이 대화에 보이고, 에이전트가 검토를 시작합니다.

2. 답 글과 분류 보드를 읽습니다​

검토가 끝나면 답 글에 발견 사항이 심각도, 파일과 줄 번호, 고칠 점과 함께 정리됩니다.
답 끝에는 같은 발견 사항이 분류 보드로 붙습니다.

보드에서 볼 곳담긴 것
요약 줄"보안 검토 결과 6건"처럼 전체 건수와 심각도별 건수(치명⁠·⁠높음⁠·⁠중간⁠·⁠낮음), 아직 분류하지 않은 건수(미분류)
줄마다심각도, 발견 사항 제목, 위치(파일:줄), 상태 선택
오른쪽 위보고서 내려받기

이렇게 보이면 된 것 답 끝에 "보안 검토 결과 N건" 보드가 보이고, 줄마다 위치와 상태 선택이 있습니다.

3. 적힌 줄을 직접 열어 보고 상태를 정합니다​

줄의 위치(예: Order.xml:8)를 누르면 오른쪽 파일 칸에 그 파일이 열리고 해당 줄이 강조됩니다.
그 줄을 직접 읽고, 실제 문제인지는 담당자가 판단합니다.

줄 오른쪽 상태 선택에서 미분류⁠·⁠확인⁠·⁠오탐⁠·⁠수정됨 가운데 하나를 고릅니다.
고른 상태는 요약 줄의 건수에도 반영됩니다.

상태뜻
미분류아직 판단하지 않음(처음 상태)
확인실제 문제로 확인함
오탐문제가 아님
수정됨고쳤음

보고서 내려받기를 누르면 Markdown 파일(security-review-날짜.md)을 받습니다.
보고서에는 심각도⁠·⁠상태별 건수, 심각도⁠·⁠상태⁠·⁠위치⁠·⁠내용 표, 건마다 공격 방법과 고칠 방법이 들어 있고, 바꾼 상태가 그대로 반영됩니다.

고칠 것이면 입력창에 이어서 요청합니다.
답 아래 입력창에 "심각한 것부터 1번 SQL 인젝션 수정해줘" 같은 다음 요청 제안이 뜨기도 합니다.

이렇게 보이면 된 것 발견 사항마다 실제 문제인지, 고칠지가 정해져 있습니다.

확인할 점​

볼 곳확인할 것
위치(파일:줄)발견 사항마다 해당 줄을 직접 읽고 판단합니다.
심각도보드의 심각도는 에이전트가 매긴 것입니다. 우리 시스템에서의 영향은 담당자가 다시 봅니다.
오탐실제 문제가 아닌 것으로 둘지는 담당자가 정합니다.
고친 뒤검토를 다시 실행해 같은 발견 사항이 남는지 봅니다.
발견 사항이 없을 때문제가 없다는 뜻은 아닙니다. 검토 결과는 사람이 판단할 자료입니다.

알아 둘 점​

  • 커밋하지 않은 변경이 있으면 그 변경만 봅니다. 고친 코드를 커밋하기 전에 실행하면 고친 부분만 검토합니다.
  • 범위가 넓으면 모듈 단위로 나눠 검토합니다.
  • 보안 장치 전체는 한 장으로 보는 보안에 있습니다.
