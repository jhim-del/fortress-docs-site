2.6.1​

2.5.2에서 달라진 점 가운데 쓰는 데 알아 둘 것을 모았습니다.

모든 사용자​

달라진 점설명
폴더 찾아보기작업 폴더를 Windows 폴더 선택 창에서 고릅니다. 폴더 선택… 메뉴에는 이미 쓴 폴더를 이름으로 찾는 폴더 검색…도 있습니다. 요청 보내고 이어 가기
버전 번호 위치왼쪽 위 로고 옆의 버전 번호가 빠졌습니다. 버전은 설정 › 정보 탭에서 봅니다. 내 버전 확인하기
샌드박스 상태 표시입력창 아래에 이 대화의 샌드박스가 켜졌는지 꺼졌는지 표시됩니다. 샌드박스
답 속 표와 수식답을 쓰는 중에도 굵게, 목록, 표를 그리고 수식은 그림으로 보여 줍니다. 요청 보내고 이어 가기
다른 대화 가리키기@로 대화를 가리키면 에이전트가 이 PC의 다른 대화를 읽고, 시키면 메시지를 보내거나 새 대화를 시작해 보고받습니다. 보내기와 새 대화 시작은 실행 전에 묻습니다. 권한 모드
읽지 못한 명령은 늘 묻기문법으로 읽지 못한 명령 줄은 권한 무시 모드에서도 묻습니다. 계획 모드와 묻지 않기 모드에서는 거부합니다. 권한 모드

관리자⁠·⁠보안 담당​

달라진 점설명
게이트웨이에서 정책 배포게이트웨이 3.4.0 이상에서 관리자가 정한 관리 정책을 로그인한 PC가 받아 적용합니다. 대화를 시작할 때 받고, 켜져 있는 PC는 1시간마다 다시 받습니다. 게이트웨이 3.3.0에서는 PC의 정책 파일만 적용됩니다. 관리자 정책
사용자마다 정책 상태모델을 부를 때마다 클라이언트 버전, 정책 출처, 샌드박스 상태를 게이트웨이에 알립니다. 게이트웨이 3.4.0 이상은 관리 정책 화면에 사용자마다 이 값을 보여 줍니다. 감사 로그는 지금처럼 각 PC에 남습니다. 관리자 정책
Windows 샌드박스 MXC 방식Windows 11 최신 빌드에서는 관리자 설치 없이 컨테이너 안에서 명령을 실행합니다. 이 방식에서는 PowerShell 명령만 씁니다. Windows 샌드박스 켜기
여러 사람이 쓰는 PCfortress windows-install --skip-profile-grant로 사용자 프로필 읽기 권한을 주지 않고 샌드박스를 준비합니다. Windows 샌드박스 켜기
PowerShell 도구관리자 정책으로 켜면 에이전트가 Windows에서 PowerShell 명령을 직접 실행합니다. PowerShell(…) 규칙으로 허용과 거부를 정합니다. 권한 규칙
거부 규칙과 샌드박스macOS⁠·⁠Linux에서 샌드박스가 켜져 있으면 파일 읽기⁠·⁠고치기 거부 규칙이 샌드박스 금지 목록에도 들어가고, 다른 사용자의 홈 폴더 읽기를 막습니다. 권한 규칙
세션 서버 접속 정보 보호웹 화면 서버의 접속 정보 파일은 로그인 파일처럼 어느 모드에서도 에이전트가 읽거나 고칠 수 없습니다. 권한 모드
샌드박스 시작 실패 알림켜져야 했던 샌드박스가 뜨지 못하면 처음 한 번 알립니다. Windows 샌드박스는 지금도 기본으로 꺼져 있습니다. 샌드박스

내 버전 확인하기​

어디서어떻게
웹 화면설정(Ctrl+,) › 정보 탭에서 Fortress 아래에 버전 번호가 나옵니다.
터미널fortress --version을 실행합니다.
설치 점검fortress doctor의 첫 줄에 Fortress AI 2.6.1처럼 나옵니다.

2.5.2까지는 웹 화면 왼쪽 위 로고 옆에도 버전 번호가 있었습니다.
확인한 버전을 이 문서의 오른쪽 위에서 고르면 그 버전의 페이지를 봅니다.
새 버전은 fortress update로 받습니다.
